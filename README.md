# Зависимости
Для проекта используется библиотека Ultralytics, обеспечивающая обучение, валидацию и инференс моделей YOLO.

Версии основных библиотек фиксируются в requirements.txt, чтобы упростить воспроизведение экспериментов в другом окружении.

Установка зависимостей:

python -m venv .venv

Активация виртуального окружения в Windows:

.venv\Scripts\Activate.ps1

Установка зависимостей:

python -m pip install --upgrade pip
pip install -r requirements.txt

# 0.2. Загрузка датасета

Датасет: HomeObjects-3K.
Источник: https://github.com/ultralytics/assets/releases/download/v0.0.0/homeobjects-3K.zip

Каталог датасета в проекте: data/, относительно корня проекта.

Структура данных:

Изображения для обучения: data/images/train/

Изображения для валидации: data/images/val/

Разметка для обучения: data/labels/train/

Разметка для валидации: data/labels/val/

# Каталог Ultralytics (datasets_dir): 
Значение datasets_dir, полученное через ultralytics.settings, показывает каталог датасетов, настроенный в текущем окружении Ultralytics.

В используемом окружении было получено следующее значение:

C:\Users\ilena\source\repos\PythonApplication1\PythonApplication1\datasets

Это значение относится к настройкам конкретного окружения и не должно использоваться как универсальный путь в коде проекта. Датасет в данном проекте хранится отдельно — в каталоге data/ относительно корня репозитория.

Для определения расположения файлов проекта в Python используется pathlib.Path. Например, если скрипт находится в каталоге scripts/, корень проекта определяется так:

from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
DATA_DIR = ROOT / "data"

Пути к конфигурациям и данным формируются относительно ROOT. Это позволяет запускать проект в другом каталоге и на другом компьютере без ручной замены абсолютных путей при условии сохранения структуры проекта.

# Подготовка данных для запуска проекта

1. Склонировать репозиторий.
2. Скачать архив датасета из указанного источника.
3. Создать в корне проекта папку data/, если её ещё нет.
4. Распаковать содержимое архива так, чтобы папки images/ и labels/ находились непосредственно внутри data/.
5. Установить зависимости из requirements.txt.

# 1.1. Базовый конфиг датасета

Конфигурация датасета находится в файле configs/data_full.yaml и содержит корневой путь к данным (path), пути к обучающей (train) и валидационной (val) выборкам, а также словарь имён классов (names), сопоставляющий идентификаторы классов их названиям. Относительные пути к выборкам разрешаются относительно каталога, указанного в path. Для каждого изображения Ultralytics автоматически ищет соответствующий файл разметки в каталоге labels, заменяя компонент пути images на labels и расширение изображения на .txt; имена файлов изображений и соответствующих файлов разметки должны совпадать. Корректность конфигурации проверяется вызовом model.val(data=str(ROOT / "configs" / "data_full.yaml")) на валидационной выборке val.

# 1.2. Собственный test-сплит без копирования файлов

Из обучающей выборки случайным образом выделено 10% изображений для тестирования с фиксированным seed=14, чтобы обеспечить воспроизводимость разбиения. Пути к оставшимся 90% изображений записаны в splits/train_90.txt, а пути к отложенным 10% — в splits/test_10.txt. Исходные изображения и файлы разметки не копируются: для разделения используются только текстовые списки путей. В конфигурации configs/data_split.yaml параметры train и test ссылаются на соответствующие списки, а val указывает на исходную выборку images/val. Ultralytics автоматически находит файлы разметки по путям к изображениям: заменяет компонент images на labels и расширение изображения на .txt, поэтому отдельные списки файлов разметки не требуются. Работоспособность тестового сплита проверяется вызовом model.val(data="configs/data_split.yaml", split="test") с моделью YOLO26n.

# 1.3. Датасет-подмножество с перенумерацией классов

Скрипт `scripts/make_subsets.py` создаёт отдельный датасет data_furniture/, содержащий пять классов: bed, sofa, chair, table и wardrobe. Идентификаторы исходных классов перенумеровываются в диапазон от 0 до 4, а строки разметки остальных классов удаляются. Изображения, на которых после фильтрации не осталось целевых объектов, сохраняются вместе с пустыми файлами разметки. Такие отрицательные примеры помогают модели учиться не обнаруживать выбранные классы на изображениях, где их нет, и могут снижать количество ложных срабатываний. 
После формирования подмножества рекомендуется проверять его целостность с помощью assert:

все идентификаторы классов находятся в диапазоне от 0 до 4;

файлы изображений и разметки соответствуют друг другу;

все пять выбранных классов имеют правильное сопоставление идентификаторов и названий;

структура каталогов соответствует configs/data_furniture.yaml.

# 1.4. YAML с аргументами обучения

Параметры базового обучения модели YOLO26n вынесены в configs/train_baseline.yaml. Конфигурация содержит настройки количества эпох, размера изображений и батча, оптимизатора, скорости обучения, регуляризации, сохранения результатов и воспроизводимости. YAML-файл загружается с помощью yaml.safe_load, после чего параметры передаются в model.train(**cfg). Это позволяет изменять настройки обучения без редактирования Python-скрипта.

Аналогичные параметры можно задавать через командную строку Ultralytics CLI:

yolo train model=yolo26n.pt data=configs/data_split.yaml epochs=15 imgsz=448 batch=8 device=cpu workers=4 seed=0 deterministic=True fraction=0.3 project=runs/homeobjects name=E1_Baseline

CLI-команда позволяет переопределять параметры без изменения YAML-файла. Для воспроизводимости эксперимента необходимо сохранять использованную команду и конфигурацию.
